# i18n

Code: [src/shared/i18n/](../src/shared/i18n). Languages: English (`en`) and Vietnamese (`vi`). No i18n library.

## How it works

- [en.ts](../src/shared/i18n/en.ts) is the source of truth for keys (`MessageKey`); [vi.ts](../src/shared/i18n/vi.ts) is typed `Messages` (`Record<MessageKey, string>`), so a missing or extra key fails type-checking.
- [I18nProvider / useI18n](../src/shared/i18n/i18n-provider.tsx) expose `t(key, params?)`, `language` and `setLanguage`. `useI18n` throws outside the provider.
- `t` replaces `{name}` placeholders from `params` (e.g. `common.pageOf`); an unknown placeholder is left as is.
- Initial language ([language-storage.ts](../src/shared/i18n/language-storage.ts)): saved value, else `vi` if `navigator.language` starts with `vi`, else `en`.
- The choice is saved in `localStorage` under `app.language`. Access is wrapped in try/catch, so the app works (without persistence) when storage is unavailable.
- `document.documentElement.lang` and `document.title` (`app.name`, "Nexus Gate") are kept in sync with the current language.
- [LanguageSwitcher](../src/shared/components/language-switcher.tsx) is a `<select>` in the app header (also shown on the startup error screen). Options come from `LANGUAGES`; option text comes from the `language.<code>` keys.
- Enum labels: [labels.ts](../src/modules/device-management/ui/labels.ts) exports `STATUS_LABEL_KEYS` and `MAINTENANCE_LABEL_KEYS` (enum value to key); callers render them with `t(...)`.
- Other key groups: `theme.*` (seven accents), `colorScheme.*` (light/dark/system), `settings.label`, `audit.*` (audit fields, `audit.unknown`), `common.showing` / `common.pageOf` (list paging), `category.*` (tree, expand/collapse all, row actions).
- The six category validation codes map to `error.validation.category*` (`categoryNameRequired`, `categoryNameDuplicate`, `categoryDepthExceeded`, `categoryCycle`, `categoryInUse`, `categoryHasChildren`).
- Formatting helpers live in [labels.ts](../src/modules/device-management/ui/labels.ts): `formatNumber` (`Intl.NumberFormat`), `formatDate` and `formatDateTime` use `LOCALES` (`en` -> `en-US`, `vi` -> `vi-VN`); an invalid date is returned unchanged.

- Expense-tracking keys: `expense.*`, `launcher.expense.*` and the validation codes `expense_*`, `statement_month_invalid`, `payment_method_*`, `total_months_*` (`error.validation.*`).

## Error translation

[translateError](../src/shared/i18n/translate-error.ts) maps by the stable `code` on the [shared errors](../src/shared/errors.ts) (they stay UI-free):

- `ValidationError`: `code` (`name_required`, `quantity_invalid`, `status_invalid`, `maintenance_type_invalid`, `date_invalid`, the six `category_*` codes, `unknown`) maps to a catalog key.
- `NotFoundError` / `AuthError` / `NetworkError`: generic text per class.
- Anything else: `error.unknown`. Raw messages are never shown by `translateError`.

Startup and render errors ([main.tsx](../src/main.tsx), `ErrorBoundary`) show `app.startFailed` / `app.error` with the raw message as detail.

## Add a key

Add it to `en.ts`, then to `vi.ts` (the compiler enforces it). To translate a new validation message, also add a code to `ValidationCode` in `shared/errors.ts` and map it in `VALIDATION_CODE_KEYS` in `translate-error.ts`.

## Add a language

1. Add the code to `LANGUAGES` and a locale to `LOCALES` in `language-storage.ts`.
2. Create a catalog typed `Messages` and register it in `CATALOGS` in `I18nProvider.tsx`.
3. Add a `language.<code>` key to every catalog (the switcher lists `LANGUAGES` automatically).
4. Optionally extend `detectInitialLanguage` for browser detection.

## Limits

Simple `{name}` interpolation only; no pluralization; catalogs are bundled (no lazy loading).
